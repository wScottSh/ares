## Decisions-so-far gist

**MM buffer placement (#23):** color fb1 0x80000500 (bank 0) / fb0 0x807DA800 (bank 7), Z 0x80383AC0 (bank 3). Color and Z never share a bank, so color/Z alternation costs 0 row misses. Z instead shares bank 3 with the RDP command ring (0x803CEB10..0x803E6B10), the work buffer and the upper audio heap.

Detail. The framebuffers are linked at fixed addresses (`spec/spec:8-12,797-802`, `include/buffers.h`). Z+work and then the 96 KiB RDP ring are the 2nd and 3rd `malloc` calls on the fresh system heap at 0x803824C0 (`graph.c:367-375`, after `Regs_Init`'s RegEditor). Addresses come from an allocator replay (script in the doc appendix).
- Cross-check: the same chain started 0x10AC0 (= #21's "66.7 KiB") higher reproduces #21's measured bench ring address 0x3DF5D0 exactly. Whether #21's 66.7 KiB came from an independent source is unchecked.
- Under the #4 model, each buffer misses only on entering a new 2 KiB row. That is ~76 rows per full-screen pass, ≈0.32 misses per line per buffer (computed).
- Bank-3 conflicts are the RDP's own: Z vs ring fetch (136–273 KB/frame) and RSP chunk writes into the ring.
- VI always scans the other color bank. Its collisions are CPU and texture traffic:
  - bank 0: hot code text (z_actor, z_bgcheck, z_camera, z_collision_check, effects), boot/libultra text, and the skybox texture buffer;
  - bank 7: the top of the Play THA, where the Kaleido area holding ovl_player_actor code sits (inferred), plus gHiBuffer pause/picto scratch.
- Hi-res (Bomber's Notebook) has no Z buffer: `gZBufferHiRes` is never assigned.

## Choices made within scope

- Bank model is #4 B6 (bank = addr[22:20], 1 MiB banks, row = addr[19:11]).
- Play-arena interior addresses are scene-dependent. I gave the allocation order and bounds, not computed addresses.
