## What changed

- **The RDP is a timeline actor** (`ares/n64/rdp/timed.cpp`). A `DPC_END` write starts the command DMA. Bursts land in a 30-dword FIFO (`rdp.cmd-fifo-dwords`) and `DPC_CURRENT` advances at each landing. The command processor dispatches one command at a time and stays busy for its compute cost. `SYNC_FULL` raises the DP interrupt when it retires, not inside the RSP's `DPC_END` write.
- **`rdp/timed.hpp`** holds the pure model, testable without a timeline: `Dpc` (START latch, END extend, START/END double buffer with END_VALID, DMA_BUSY, PIPE_BUSY/START_GCLK until SYNC_FULL), BUFBUSY/PIPEBUSY/TMEM counters as functions of time, `cost()` per command, the fetch request size and `fetchLatency()`.
- **Costs** come from behavior rows: setters `rdp.setter`, syncs `rdp.sync-*`, Sync Full `rdp.sync-full` (new, model-choice), primitives `rdp.primitive-base` + per span `(px + rdp.span-dead-pixels)` at the cycle rate + `rdp.span-line-gap` (both new, fit to Thar0), fill/copy `rdp.fill-copy-rate`, loads `rdp.tmem-load-rate`, X bus fetch `rdp.xbus-fetch-rate` (new, model-choice).
- **Command fetch seam for T6/T13:** `RDPTimed::fetchLatency()` charges one uncontended RDRAM read burst from the existing `ri.read-hit`, `ri.octbyte` and `ri.overhead-rdp` rows. T6/T13 replace that one function with a `DpCommand` RI post whose grant lands the words (`RDP::step`'s landing branch).
- `DPC_TMEM_BUSY` reads its counter (the `data == 7` test is gone). STATUS bits 6-9 clear the counters, not the busy flags.
- **Engine** (`rdp/engine/`): reports work (pixels, 64-bit words, spans, load bytes) instead of its own cycle law. A dispatch resolves any unsynced-write hazard hold with the commands already in the FIFO and then settles, so no held primitive or queued span crosses emulated time and saving never mutates. The untimed `rdp_process_list` walk, the register mirror and the interrupt callback are deleted.
- **Timeline:** `wake()` records the earliest woken time and `Actor::run`/`fireEvents` stop at `timeline.limit(limit)`. The RSP's `DPC_END` write wakes the RDP inside `RSP::run`; the RDP's step must come before the RSP's later steps. This also closes verify-49's stale `fireEvents` limit. Two `unit:timeline` cases, each failing on its mutation.
- **Tools:** `unit:dpc-regs` (`tools/n64-timing/tests/dpc-regs.cpp`), `ARES_DPLOG` trace + `dplog-check.py`, `checks.tsv` rows `unit:dpc-regs`, `rdpstat:dpc-sequencing`, `rdpstat:xbus`. mmbench `filesel-rotate` waits for `windowRot >= step` (the game now sometimes updates twice in one field after a long frame, and the exact-value wait never matched).

## Deviations

1. `rdp.primitive-base` 14 -> 12 (basis fit). The cen64 14 includes the 2-word fetch, which the front end now charges as command fetch. New fit rows `rdp.span-dead-pixels` 2 px and `rdp.span-line-gap` 2 rclk solve Thar0's 324 and 646 clocks per 320-px line. One rectangle size only, so the split is inferred; triangles use the same base (no reference).
2. Sync Full drain is a new model-choice row equal to the Sync Pipe stall (cen64's choice) until T13 models memory.
3. Fetch requests at most one burst and never more than the FIFO has room for; waiting for room for a full burst deadlocked MM (partial 22-dword triangle in a 30-dword FIFO).
4. DMA_BUSY means CURRENT < END (transfer incomplete), not "a burst in flight"; the rdpstat dpc ROM expects it set while the FIFO is full.
5. FREEZE stops dispatch, not fetch (n64-systemtest author note: CURRENT reaches START+240 while frozen). Unfreezing sets PIPE_BUSY/START_GCLK as the old `flushCommands` did.
6. Unsynced-write hazard holds see only the commands already in the FIFO at dispatch. T15 replaces the hold model.
7. Files beyond the plan's list: `rsp/rsp.cpp` and `timing/timeline.hpp` (wake limit), `system/serialization.cpp` (state version `v153.5-dpc`), `tools/n64-run/n64-run.cpp` (stats columns), `mmbench.py`, `build.sh`, tests CMake, READMEs.
