## What changed

The paraLLEl position hash that the port used for RDP noise is gone. In its place are Thar0's three hardware LFSRs, stepped by the RDP clock.

- `RDPTimed::NoiseLfsr` (`rdp/timed.hpp`) holds three Fibonacci LFSRs: `x^29+x^2+1`, `x^28+x^3+1` and `x^27+x^5+x^2+x+1`. All three are all ones at power-on, c runs one step ahead, and every RDP clock is one step (rdp-noise.md). The state depends only on the clock count. A gap of up to 64 clocks steps; a longer gap is a GF(2) matrix power (`power[k]` = M^(2^k)). The state is not saved. `at()` gives the same answer whatever it was asked before.
- Engine (`engine/rdp_core.c`, `rdp.c`, `rdp.h`). `rdp_seeded_noise`, `m_primitive_counter` and `m_primitive_offset` are deleted. Before each span runs, `startSpan` calls `rdp_render_set_span_clock(first, clocksPerPixel)`. The first clock is the span start rounded up to an rclk edge, plus `rdp.noise-pixel-offset`. Clocks per pixel is `pixelClocks(cycle, 1)`, so 1 in 1-cycle and 2 in 2-cycle. Pixel j in walk order samples the LFSRs at `first + j * step`.
- Consumers:
  - Combiner NOISE is `abc100000` (Thar0).
  - `G_AD_NOISE` is `abc`, after Angrylion `(noise >> 6) & 7`. New row `rdp.noise-alpha-dither`, model-choice: no hardware data, and MiSTer conflicts.
  - `G_CD_NOISE` and the `G_AC_DITHER` threshold have no hardware source. Both read the top three bits of each register. New row `rdp.noise-dither-bits`, model-choice.
- `SerializerVersion` is now `v153.11-noise`, because the engine state lost a field.
- Tests:
  - `tools/n64-timing/tests/noise-lfsr.cpp` builds `n64-timing-noise`, which runs four ctest checks: `unit:noise-lfsr`, `noise:a`, `noise:b` and `noise:c`.
  - `noise-datasets.hpp` is generated by `import-noise-datasets.py` from Thar0/RDP-Noise `rdp_noise_lfsr.c` (Unlicense, e7f6c7f). The script parses the file as text and runs no code from the clone.
- romgen `--suite noise` builds `noise-rect-1016.z64`, a port of `rdp_noise.c`. `decode.py` is fb2data's clamp inverse, `n64-timing-noise rect` is the checker, and `run.sh` runs both.

## Deviations

1. `NoiseLfsr` lives in `rdp/timed.hpp`, not `timed.cpp`. That way the host test drives it without a timeline, as dpc-regs drives `Dpc`. `timed.cpp` only sets each span's clock.
2. The 2-cycle sampling clock (the first of the pixel's two) and rounding the span start up to an rclk edge are model choices. Both are recorded in the `rdp.noise-pixel-offset` note.
3. `G_CD_NOISE` and `G_AC_DITHER` have no hardware source. Deleting the hash forced a choice, so `rdp.noise-dither-bits` (model-choice) gives one. Its check is `pending:no-corpus`.
4. Files beyond the plan: the engine files named above, `system/serialization.cpp`, `build.sh` (new target), tests, the romgen suite, checks.tsv and behaviors.tsv rows.
5. Commit trailers use the session attribution line.
