Map gist (one line): 15 public corpora inventoried. Only Thar0/RDP-Timing-Tests has console RDP counter data, and it matches the jgemu span law within 0.2%. Of the 15 #16 requests, 0 are fully answered by public data, 12 partly, and 3 have none (#5, #8, #19). MM bench scenes also have none. No corpus states the console model or whether an Expansion Pak was installed.

Shortlist (harness wiring order):
1. Thar0 RDP-Timing-Tests @ a81ced93b28d (MIT). 100 fill-rect configs, BUFBUSY/PIPEBUSY min/avg/max. The alpha all-fail configs are exact (77,772 clk 1-cycle), so they can be a zero-tolerance test. Needs debugf/ISViewer capture from the emulator.
2. nemu64-test timing group @ 9a8b9f7d94ee (MIT). Self-checking CPU cache, uncached-load, write-buffer, and COUNT:DP_CLOCK checks.
3. rasky n64-systembench @ 845635c68c75 (no license, run externally). Self-graded CPU, RCP-reg, PI, and SI latencies.
4. rasky n64_pi_dma_test @ fea460b063f6 (no license, run externally). 64 alignments x 383 lengths of PI DMA timing, plus register goldens.
5. snapper64 @ e1cd8a61fc43 and repeater64 @ 6ec3811b27ae (MIT). Pixel refs that catch RDP state-update ordering changes.
6. Thar0 RDP-Noise @ e7f6c7fb36c1. Replays the console LFSR arrays.

Key derived numbers (Thar0 ms x 62,500; arithmetic is ours):
- 1-cycle, every pixel failing alpha: 77,772 = 240x324+12. 2-cycle: 155,052.
- Plain write, 1-cycle: measured 80,462. The jgemu law predicts 80,294.
- FB+ZB in the same bank costs about 205 clk per line more than separate banks.
- PIPEBUSY stays within 0.2% of BUFBUSY under stalls. That suggests PIPEBUSY includes stall cycles (inferred, since DPC_CLOCK was not recorded).
