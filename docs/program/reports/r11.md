## Findings

- **The threads hold no MM hardware capture [measured].** All four YouTube links in ares#2320 are ares captures: the titles say "ares nightly", and the "60 VPS" status bar is in frame. MiSTer#27 has no capture. The only hardware capture is meauxdal's OoT USA attachment on #2320.
- **I measured MM on two public hardware recordings instead.** Downloading with yt-dlp was not blocked.
  - U is UltraNova5000 `57fdDCbAs28`, with both files empty.
  - W is WatchmeplayNintendo `UpYHyLo3-aQ`, with two named files.
  - Both chains were checked on 20 fps gameplay (mean 3.0 capture frames per game frame). U's rig also records OoT's file select at a strict 2-field cadence, so the rig can show 30 fps.
- **Results, in fields per game frame [measured]:**

  | State | U (empty files) | W (two named files) |
  |---|---|---|
  | Main screen idle | 1.00 (pulse 0.991, fit 1.02) | 2.00 (fit 1.96 to 2.04) |
  | Options idle | 1.00 | not in W |
  | Fade-in | 1 | 2 |
  | Window rotations | 1.20 overall (10 rotations) | 1.50 to 1.57 |

  OoT's file select is 2.00 in every file-select state, in capture O and on U's rig.
- **Method.**
  - Per-frame differencing for moving bursts.
  - For idle states, the cursor-pulse period. `FileSelect_PulsateCursor` has a period of exactly 40 game frames, so fields per frame = period × 59.826 / 40.
  - Control on the ares capture: 1.00.
- **Fork comparison.** The bench `filesel` scene (empty files, idle main screen) gives 1.0000 [cited, mmbench report]. That matches U, but only because the fork's RDP takes zero time. With named files the fork would give 1 instead of 2 [inferred].
- **Limiting unit: the RDP [inferred].**
  - The fork's RSP is busy 4.95 ms median and 5.69 ms max per field, gfx plus audio [measured, `fields.tsv`]. Units are taken from the tool README and not re-derived.
  - RDP estimate from the display lists: about 333 k clocks (5.3 ms) of compute and about 0.85 MB of traffic. The full-screen RMW fill is a quarter of that compute. With the stall share in `rdp-memory-traffic`, that gives 10.7 to 16 ms.
  - The frame cost depends on screen area. Rotation frames with the window near edge-on fit in 1 field [measured].
  - CPU time was not measured, so the CPU is not excluded by measurement.
- **Acceptance check (end of the doc).** Empty files and idle main screen: 1.00 (mean ≤ 1.05, at least 95 % of frames at 1 field). Two named files and idle main screen: 2.00 (1.90 to 2.10, at least 90 % at 2). Both rows must pass: row 1 alone is met by a model with zero RDP cost, and row 2 alone by any model that is too slow. Secondary rows: Options idle 1.00, rotation 1.0 to 1.6.
