## What changed

- `ares/n64/ri/bus.hpp` is the RDRAM channel model (`RiBus::Channel`), which is pure and host-testable:
  - per-burst arbitration by (rank, arrival, requester, sequence), where refresh beats VI, which beats first-come first-served (the `ri.rank.*` rows);
  - 8 banks, each with an open row and a dirty bit;
  - NEC uPD488170L wire costs: hit, clean retry 22 tc, dirty retry 30 tc, 4 tc per octbyte;
  - per-direction overhead and post gap;
  - refresh at 52/54 rclk, which clears dirty bits and leaves rows open;
  - per-requester counters.
- `ri/bus.cpp` makes it the timeline's Bus actor. The RI moves each burst's bytes between `rdram.ram` and the client at grant time.
- `rdram.ram` is private. The friends are RI, MI (debugger path plus repeat and EBus modes), and `Loader` (the n64-run host view). AI, PI, PIF (SI), RSP, VI and RDP are named friends until T8, T11 and T13.
- `cpu/sysad.hpp/.cpp` is the VR4300 port:
  - a 4-entry write buffer: 1 pclk per store until it fills, slots released on "has a space";
  - reads wait behind every older write;
  - a dirty D-miss fills first, then queues its victim as a 2-entry block write;
  - posted register, PI and PIF writes take effect at drain time, at `sysad.register-write` = 5 rclk after the drain starts;
  - uncached reads and D-fills and I-fills go to the RI as CpuSysAD bursts. The CPU blocks only here (an await loop over the timeline), and its clock runs on through the stall.
- The fixed SysAD paths are computed in code from the measured totals, minus the modeled RI time at the measurement's row state, minus the mean rclk-edge wait:
  - uncached read 32 total, at a row hit;
  - D-fill 41 total, at the clean row miss the nemu64 loop produces;
  - I-fill keeps the legacy 48-pclk stall until T7d.
- Refresh is posted at each VI line event while the VI is active.
- The D-hit +1 is removed.
- RCP register reads cost `cpu.rcp-register-read` (22 total). Before, they cost 21.
- Timeline:
  - one trace record per event and per actor step. `RSP::run` and `RDP::run` call `timeline.record()` for each later step.
  - `earliest()`, `record()` and `actingAt()` are new.
  - schedule() lowers `woken`, and the wake min survives nesting. This is merged onto T12's `woken`/`limit()` API.
- RI channel serialization is canonical: shift-remove, a per-requester sequence, and live entries sorted on write.
- `n64-run` prints an `ri grants_cpu=... grants_refresh=...` line, and mmbench files that line with the host stats.
- Unit tests:
  - `unit:ri-cost-table` (tests/ri.cpp);
  - unit:timeline cases for trace independence from batching (events, actor runs);
  - wake-in-step coverage, which T12's equivalent cases now carry after the merge.
- The behaviors.py self-test moved to the MULT legacy site.

## DEVIATIONS

1. The arbiter lives in the existing `struct RI` (Actor plus registers). The standalone model is `namespace RiBus` in ri/bus.hpp. The sketch had `RI::Ri`, which clashes with `struct RI`.
2. `Burst` carries a client `tag` in place of a data pointer. The client returns its buffer at grant (`Client::buffer`), so pending bursts hold no host pointers and survive save states. The byte move covers CPU sizes only (1/2/4/8/16/32). T8 extends it for 128 B DMA bursts.
3. There is no `requesterSpecs` table, because only CPU and refresh post in T6. Every requester has a 1-unit request latency (new row `ri.request-latency`, model-choice), and the per-direction overhead (DP uses `ri.overhead-rdp`). The response latency is folded into the SysAD paths.
4. The SysAD fixed paths are constexpr expressions over the measured rows, not TSV rows. Two drain periods are rows: `sysad.rdram-write-period` and `sysad.rdram-block-write-period`, both 12 rclk, basis fit with fit-from and verify-is-fit notes. `sysad.register-write` is 5 rclk, model-choice: MiSTer floor, no measurement.
5. The D-fill path is derived at a clean row miss, because the nemu64 miss loop evicts with a line 8 KiB away in the same bank. A same-row fill is therefore 8 pclk cheaper. systembench saw no row penalty for uncached reads, which is a tension with this. The ADR rule (row state of the measurement) decided it.
6. Refresh fires only while the VI is active (VI_CTRL type != 0). Evidence: with refresh on blank VI too, nemu64 VI-off uncached loads averaged about 35.5 against hardware's 32.54, and with it off they average about 32.3. n64brew RDRAM_Interface says refresh also runs before VI init. That conflict stays open.
7. The I-fill goes through SysAD::fill now, ahead of T7d, at the legacy 48-pclk uncontended stall. The I-cache CACHE writeback keeps the legacy 48 and posts its 32 B line as a 4-slot block write. Without this, I-fills would read RDRAM around the write buffer.
8. There is no write fast path. An idle write granted at once changed the field-boundary state hash between normal and step-capped runs, so I removed it. CPU reads keep `RI::postAndDecide`, the fast path when `d <= horizon()`, and stepcap proves it equivalent.
9. Timeline changes beyond the plan:
   - per-event and per-step trace folds;
   - `record`, `earliest`, `actingAt`;
   - schedule() lowering `woken`.
   T5's fold-per-batch made trace_hash depend on catch-up targets. That was latent and surfaced as stepcap failures once T6 added steps.
10. Files beyond the plan's list:
    - mi/mi.hpp gains `repeating()` and `ebusTest()`;
    - n64-run and mmbench get the `ri` line;
    - README;
    - rsp/rsp.cpp and rdp/timed.cpp record each later step;
    - behaviors.py self-test site;
    - tests/CMakeLists and timeline.cpp dispatch take the test name as an argument.
11. The save-state version is v153.6-sysad.
12. Debugger reads (emux XLOG, readDebug) overlay queued writes (`SysAD::forward`). n64-run's own peek and frame-dump paths read RDRAM without the overlay.
13. Commit trailers use the session attribution (Claude Opus 5.5). The merge commit 9cb6723cc also carries the RDP::run `record()` line T12's actor needed.

## For the next unit

- A bus client implements `RI::Client::buffer(burst)` and `granted(grant)`, calls `ri.attach(requester, this)` at power, and posts with `ri.post(burst, at)`. `post` wakes the Bus. Bursts are at most 128 B and never cross a 2 KiB row; there is no `split()` yet (unit:ri-split is undefined).
- The RI's byte move switches on `bytes` for CPU sizes. Extend `RI::run` for DMA bursts.
- An actor whose run() takes several steps must call `timeline.record(next.at, id)` for each step after the first. If it does not, stepcap fails on trace_hash.
- Anything serialized must not depend on host posting order. The RI pending array is canonicalized on write.
- CPU stores to RCP registers take effect `sysad.register-write` (5 rclk) after their drain starts, with `timeline.now()` equal to the drain time. Device code that reads `cpu.clock` inside a register write sees a later time. Use the passed `thread.clock`.
