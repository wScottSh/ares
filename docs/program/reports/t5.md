## Review of the inherited WIP

I kept the prior agents' design: the timeline header, the RSP as an actor, events at absolute times, COMPARE as one event, RCP access sync, the unit test and the step-cap tooling. It matches ADR Decision 1 and the sketch. I fixed or changed these:
- `Thread::actor` defaulted to CPU, so any scratch `Thread` (the RSP disassembler's included) would catch the timeline up. The default is now Count, CPU and RSP name themselves, and the `Thread::debugger()` helper and its 6 call-site edits are reverted.
- `CPU::main` ran one instruction past the field boundary, because it tested `vi.refreshed` before the catch-up that fires the VI line. It now tests after. MM field 1 cpu_cycles then equals the base.
- `schedule()` could write past its 64-entry array. It now aborts when full.
- Speed: the first head was 0.5-1.0 s slower than the base on the sct scene. The scans now walk only the event heap and the attached actors, skip the floor loop when the stack is empty, and the top-level CPU catch-up takes its horizon from its last scan. Interleaved, sct went 21.6/21.7 s -> 20.5/20.4 s, against a base of 20.8/21.0 s.
- unit:timeline missed two defects in mutation runs: a Parked actor stepped by time alone, and a floor that ignores the stack. I fixed both cases and added one.
- Cosmetic: the leftover block in VI::line.

## DEVIATIONS

1. `Actor::step` is `run(limit)`: one step, then more while the next step starts before limit. The contract says a run that posts earlier than its limit must return after that step. No current actor does so.
2. `Event` is `{at, kind}` with no arg. It lives in a sorted 64-entry array (abort when full), not a binary heap; there are 18 kinds. The timeline gains reset, wake, pending, now, setStepCap and refreshHorizon, and cancel returns the latest cancelled time.
3. `await` is not implemented; it waits for the T6 bus.
4. The RDP is not an attached actor. It renders synchronously at DPC_END and has no timed state until T12. `legacy.rdp.step-quantum` is gone, and DPC_CLOCK comes from `clockOrigin`.
5. `EventKind` lives in timing/events.hpp, not devices/events.hpp (T8).
6. `TraceHash::fold` is removed. The timeline's rolling hash is serialized into the state, and the per-field state hash carries it.
7. The on-stack skip in the argmin scan stays as defense, though no test can observe it.
8. The idle VI posts a line event every 0x800 VCLKs for host liveness (allowlisted). The PIF stops polling at Run. The `legacy.rsp.halted-quantum` and `legacy.vi.inactive-line` rows are removed.
9. `rsp.profile.haltedCycles` no longer increments.
10. Files beyond the plan's list: call-site migrations in cartridge, 64DD, PI, SI and PIF; step-cap mode in determinism.sh and mmbench.py; the n64-run instruction-count line; tests CMake; build.sh builds n64-timing-tests; README; checks.tsv (`stepcap` command, `unit:timeline` row); lint-literals call names; `scheduler.tie-rank` also checks `unit:timeline`. Save-state version is v153.4-timeline.
11. Commit trailers use the session attribution line (Claude Opus 5.5), not the brief's.

## For the next unit

- To add an actor: inherit `Timing::Actor`, set `Thread::actor` in the constructor, `timeline.attach` at power, and call `timeline.wake(id)` whenever another actor's action makes it runnable earlier. Inside `run`, return once you post anything earlier than `limit`.
- Device timers use `scheduleAfter(EventKind, delay)` (now = handler time inside a handler, cpu.clock otherwise) or `timeline.schedule({absolute, kind})`. Add the handler in timing/timeline.cpp `fireEvent`.
- Every `Memory::RCP` read and write already syncs. A new cross-device access path must call `thread.sync()` first.
- Run stepcap with `tools/n64-timing/determinism.sh --step-cap ROM`. MM runs every mmbench scene.
