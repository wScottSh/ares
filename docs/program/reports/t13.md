## What changed

- Every RDRAM touch in the engine now goes through windows (`rdp_memwin`): pixel, Z, hidden bits, TMEM load sources and command fetch. `rdp_read_data` and the fitted stale-read hack are deleted. `Rdram::ram`'s friend list is now RI, MI and Loader. MI predates T13.
- Spans cross emulated time. The poly manager keeps them queued, and the RDP actor runs each one after its DpColor/DpDepth snapshot lands. Chunks are cut at 64 B half boundaries. Write-back is one burst per contiguous written run, split at 128 B and at 2 KiB rows. Fill writes use DpFill. TMEM loads plan their rows with a dry run and stage them through DpTexture. Command fetch is a DpCommand post, which replaces T12's `fetchLatency`.
- The RDP has one memory interface. Each burst holds it for the RI wire time plus `rdp.mem-overhead-read` (21 rclk per 64 B) or `rdp.mem-overhead-write` (19.5 rclk per 64 B), scaled by burst bytes. A read's data is usable `rdp.span-read-latency` (12.5 rclk) later. One read per image is outstanding at a time. `ri.overhead-rdp` is now 0, derived.
- The 1PRIMITIVE barrier waits for max(last write-back landed, last span end + 35). Sync Load/Pipe/Tile stall the pipeline after the spans ahead of them. Sync Full retires when the last write-back lands. Phantom spans (the slot after a primitive's last span) take no time.
- Save states carry the queued spans, the slot windows, the ports, the pipeline and any TMEM load. Pool items, aux records and span params are zeroed when handed out. `SerializerVersion` is v153.10-rdpmem.
- An engine bug is fixed: the Z dz hidden bits now sit at the Z halfword's own index. MAME's byte-address base had put them in another image's plane.
- New tools: `rdpstat-1prim` ROM, check rows `rdpstat:1prim` and `mm:filesel-acceptance`, the `n64-run --rdp-fields` option, and an `ri_dp` stderr line with `gclk_off_share` and `mem_misses`.

## Deviations

1. Halves never stall the pipeline: write-backs queue at the interface. The data lives in 4 per-span slot windows, not in literal 64 B halves. The reason: 2-cycle IM_RD lines take as long as 1-cycle ones on hardware (675 vs 681 rclk).
2. One RDP memory interface with the per-burst cost on the RDP side and 0 on the channel. The sketch had per-image ports plus `ri.overhead-rdp`. The reason: Thar0 VI writes-only configs slow only 0.5-1.5%.
3. Span reads are cut at 64 B halves. A TMEM load fetches all its rows and then applies them. It waits for the pipeline to be empty and the Z halves to drain. TMEM rows reuse the span-read costs, which is an assumption.
4. The 1PRIMITIVE dead cycles count from the last span, per the SDK's wording, not after the last write, which is the ADR's "plus".
5. Files beyond the plan's list: ri/bus.{hpp,cpp}, rdram.hpp, n64.hpp, system/serialization.cpp, n64-run, checks.tsv, the rdpstat suite (stale.py, routines, sets, run.sh, README), dpc-regs.cpp and the engine README.
6. The literal-lint allowlist has no rdp rows. The remaining 34 rows are in other subsystems, outside T13.
7. Commit trailers use the session attribution line (Claude Opus 5.5).
