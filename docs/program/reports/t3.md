2. The header emits s64 counts of 750 MHz units, plus Ratio and bool, instead of Clock, which does not exist until T4. Switching the type is one line in constant(). Names are the mechanical CamelCase of the id, for example RiMaxBurst and RdpSpan2cycle = Ratio{1,2}.

6. Files the plan did not name: literal-allowlist.tsv, the README section, the n64.hpp include, and the CMake hook. Configure now requires Python 3.
7. The sketch's CSV-quoted cells are now plain text.
8. 8 bench ids that the table names have no ROM in R1: ifill-isolated, uncached-sizes, rcp-reg-read, pif-ram-read, pi-io-write, si-dma, wb-fifth-store and rdp-loadsz-sweep. ## For the next unit
- To add a constant, add a row and run `python tools/n64-timing/behaviors.py`. Code reads it as `Timing::Behavior::<CamelCaseId>`, in 750 MHz units. T4 should change constant() in behaviors.py to emit Clock.
- To replace a legacy cost, delete its literal-allowlist.tsv entries and its legacy row in the same commit, then run behaviors.py. If you move code above a legacy site, run `behaviors.py --fix-lines`.
- The build runs --check. A stale spec, an unpinned literal or an undefined check id fails the build.
- For results: `behaviors.py --results nemu64=<results/nemu64 dir> det=<det.txt>`. Only the nemu64 and det readers exist. T17 adds the others.
